Patterns in the reviewed Q&A

Interconnect names leave mechanisms unresolved.

Arm's cache stashing needed software and interface prerequisites; Xilinx qualified its nonblocking-mesh claim through traffic-class isolation. AWS discussed placement groups and packet-aware limiting. Topology and peak link rate did not describe congestion behavior. S1 66:07 ↗

Peak compute needs workload evidence.

Huawei and Spring Crest faced benchmark and MLPerf questions. Cerebras deferred working-system performance. Microsoft's compression comparison used different algorithms. Those answers exposed comparison boundaries that peak throughput alone could not resolve. S4 30:23 ↗

Sparse workloads make placement decisive.

Facebook described profile-guided embedding partitioning, local bandwidth versus distributed latency, and prefetch overfetch. UPMEM DPUs communicated through the CPU. Irregular accesses and host work belonged in accelerator sizing alongside dense kernels. S2 25:52 ↗

Numerical formats carry software obligations.

Intel linked its Flexpoint-to-BF16 change to software scaling. Google's BF16 and array-size answers described tested models and compiler co-design. Datatype support alone did not establish convergence, rounding behavior or utilization on real tensor shapes. S4 61:07 ↗

Integration adds power, test and trust gates.

Lakefield described known-good-die testing but left stacking limits unquantified. Tesla's dual-SoC safety intent did not specify disagreement handling. Jintide's monitor answer did not establish a complete host trust boundary. S8 26:47 ↗

Implications and concrete vendor asks

Analyst inference: these present-day acceptance tests follow from historical uncertainties. Historical statements and roadmap promises do not establish later delivery.

Fabric/interface commitment Before topology selectionSpecify ordering, traffic isolation, stashing prerequisites and forward progress. Test mixed traffic, congestion and recovery at the workload's tail-latency target.
Accelerator sizing Before using scaling graphsRequire reproducible matched algorithms, precision, batch and quality. Measure host, memory and network utilization with useful end-to-end throughput.
Sparse memory/CPU balance Before deploymentSweep embedding size, skew, locality and profile drift. Include ingestion and updates; measure prefetch overfetch, latency and effective bandwidth.
Datatype/compiler contract Before model commitmentVerify convergence, rounding and overflow at fixed quality. Profile tensor shapes and schedules; include rejected operators and porting cost in acceptance.
Integrated platform readiness Before sign-offRequest stack power, thermal headroom, die-test coverage and fault handling. Inject failures and disagreement; verify monitor privileges and service recovery.

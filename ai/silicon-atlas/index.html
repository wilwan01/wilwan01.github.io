带宽和容量上限不保证同时达到；CPU TDP 不等于整机插墙功率。下方容量模型使用独立的整机功率假设。

Mac server 的口径：本页把 Mac mini、Mac Studio 与已发布的 Mac Pro Rack 作为 Mac 服务器部署候选，不另造“Mac Server”芯片系列。Apple Silicon 是 CPU、GPU、媒体引擎与统一内存组成的 SoC；客户端 CPU 核、服务器 CPU 核和 GPU 算力不能直接相加。用于持续服务时须验证 macOS 软件栈、远程管理、断电恢复、网络和维修方案。

通用计算与代理编排

按有效任务吞吐和 p99 比较。核数增加后，调度、内存带宽和软件许可是否先成为限制？

数据库与检索

固定数据集、缓存命中率和服务水平。检查内存容量、随机访问时延、NUMA 与存储路径。

GPU 主机与数据流水线

确认设备接入、PCIe/C2C 拓扑、预处理与网络带宽。CPU 更快是否实际减少 GPU 等待？

计算方法与边界

每架节点上限 = min(⌊可用 U / 整机 U⌋, ⌊(机架 IT 功率 − 预留功率) / 整机功率⌋)。各平台机架数 = ⌈节点数 / 每架节点上限⌉；节点数为零时不占机架。上限为零且有分配时，计划不可行。

设施功率 = (Σ 节点数 × 整机功率 + 总机架数 × 预留功率) × PUE。电费 = 设施 kW × 8760 × 年数 × 电价。假设整个比较期所有节点均已部署且保持输入的平均功率；路线图只用于排期，不调整投产时间或现金流。

合计 = 整机采购额 + 电费 + 节点年度运维 × 节点数 × 年数。未计独立 GPU、机房建设、网络设备采购、软件许可、融资、税、折现及期末残值，因此不是完整 TCO。尚无业务吞吐输入，不能据此计算每任务成本或选出赢家。
